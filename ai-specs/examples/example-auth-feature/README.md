# Example: User Authentication Feature

This is a complete example of how a feature flows through the Spec-Driven Development process.

## Use cases
- Learn the structure of OpenSpec artifacts
- Understand how tasks are broken down from specs
- See how acceptance criteria map to implementation
- Reference for your own projects

## Files included
- `proposal.md` — Initial idea and scope
- `specs.md` — Functional and non-functional requirements with acceptance criteria
- `scenarios.md` — Gherkin scenarios for testing
- `tasks.md` — Implementation plan with steps

## How to use
1. Read `proposal.md` to see the initial idea and scope
2. Read `specs.md` to see refined requirements and acceptance criteria
3. Read `scenarios.md` to see how specs translate to testable scenarios
4. Read `tasks.md` to see how specs are broken into implementable tasks
5. Compare the structure with your own projects

## Key takeaways
- **Proposal** defines WHAT and WHY
- **Specs** define HOW (requirements) and WHEN (acceptance criteria)
- **Scenarios** define TESTABLE behavior
- **Tasks** define IMPLEMENTATION steps

## Note
This is a reference example, not a template. Adapt the structure and depth to your specific context and project needs.
